# 开发、验证与磁盘控制

## 工作区与长期迭代

- 开始先读 `git status --short`、`git worktree list`、当前任务记录和相关 `AGENTS.md`。记录基线提交及原有改动/快照路径。
- 同一问题的修改、复核、重试与上线续接使用一个 worktree。新任务需要隔离时用现有 Git 对象创建 worktree，不复制整个仓库或另外 clone。
- worktree 目录不提交构建产物、日志或真实配置。只提交当前任务文件；避免从含用户改动的主目录执行全量暂存。
- 任务记录建议包含：当前阶段、分支和基线、工作区、源码变更指纹、做过哪些检查及结果、产物/备份路径、发布标签和 Actions run、已部署镜像 ID、下一步。只有发布任务才需要发布字段。
- 证据应对应当前代码。未提交新文件也属于变更指纹；只记录 HEAD 或 tracked diff 会漏掉它们。代码再修改后重跑受影响的检查，不复用过期的通过记录。
- 提交采用仓库已有风格。只有当前对话授权提交、发版或上线时才执行对应动作；不要因为通用工作流将“本地提交”作为终点就扩大授权。

## 先选择必要验证

| 变更 | 合适的验证 |
| --- | --- |
| Go 局部逻辑 | 有意义的行为用例及受影响 package 的 `go test -p 1` |
| 回调/按钮 | 真实 Telebot 回调解析与序列化，反馈、边界、重复点击；URL 的真实目标 |
| 并发、队列、恢复 | 对相关包运行 `go test -race -p 1`，验证重复入库、重启、失败与状态迁移 |
| 配置 | 默认值、兼容加载、示例/文档一致性，凭据不回显 |
| 前端 | 用锁文件兼容的 Node 执行类型检查和构建 |
| 新依赖、容器入口、打包 | 针对实际运行镜像做 smoke；验证镜像中确有所需工具 |
| 发版 | 当前代码的全量 Go 检查、实际发布构建与部署核验；不把旧结果冒充本版结果 |
| 纯文档/技能 | 验证格式、引用、元数据和新增脚本行为，通常不重建应用或重跑无关 Go 测试 |

项目会 embed `web/dist`。Go 全量测试或服务构建前，确认这个目录存在且产物对应当前前端源码。前端未变化时可复用已验证的相同源码产物；不要用空目录或占位首页骗过 embed。前端变化则重新构建。

脚本按实际语言验证。Bash 修改后运行 `shellcheck -S warning` 与 `shfmt -d`；Python 新脚本至少检查语法并运行正常/失败输入。不要为了可逆小改动机械添加镜像实现的测试。

## 控制缓存与构建体积

1. 先查询可用磁盘、内存和任务自身产物；需要大小时才运行预检的 `--sizes`。不把过去的容量、工具版本、容器数写成当前事实。
2. 复用 Go 的 `GOMODCACHE`、`GOCACHE`，以及已有 npm 缓存和适配的 Node 工具链。不要给每个 worktree 复制一套 Go module cache、node_modules 或下载一个 Node。
3. Node 选择依据 `Dockerfile` 的前端构建阶段及 `webui/package-lock.json` 的 engines；不能假定系统 Node 足够新。需要时复用已有兼容环境，避免修改系统 Node。
4. 本地按资源串行执行重构建，Go 用 `-p 1`；不要同时跑多份全量测试、交叉编译和 Docker build。资源不足优先使用现有 GitHub Actions 发布构建。
5. 同一源码只保存必要的可执行文件和 smoke 产物，不再把它们复制成多份 tar/目录。初始快照、发布前配置/SQLite 备份和回滚镜像按恢复需求保留；高频临时日志集中写同一任务状态目录。成功后保留精简摘要和 CI 链接，清理本任务重复的大日志/产物，不累积多套成功构建副本。
6. 本地只构建验证需要的平台；多平台正式安装包由 Actions 的 `make release` 生成。前端或打包没有变化且已有可信产物时，不为每次文字调整重建整套镜像。

## 临时运行验证

- 使用唯一任务容器名和 `devflow/gymdl:<task>-<sha>` 测试标签。HTTP 如需映射端口只绑定 `127.0.0.1`，先确认空闲端口。
- 普通启动 smoke 用脱敏临时配置，关闭 Telegram、定时同步、目录监听和外部自动任务；测试数据放临时目录或临时卷。
- 真实平台只读检查可用镜像内 `./discovery-check -c config.yaml -platform all`，或选择单个平台。真实配置和数据按需只读挂载，输出连接状态和数量即可。确认被检查镜像包含 yt-dlp 等运行依赖；检测环境缺工具不等于登录失败。
- 不用线上账号发送测试消息、自动下载真实收藏或启用任务来代替离线验证，除非当前任务包含这些动作的授权。

## 精确清理

每次任务收尾都主动做本节的空间盘点，不因磁盘当前宽裕或用户未提醒而跳过。部署机开始清理前后记录 `df -h /`，并按 `~/.codex/AGENTS.md` 保留持久数据和恢复所需文件；Mac/Windows 开发机使用本机适用的磁盘检查方式和 AGENTS 约定，不对服务器路径或数据执行清理。结束时先列出本任务创建的资源，再逐项处理：

- 用完即移除临时测试容器；只删除本任务测试镜像标签，核对无运行容器引用。
- 删除可重建的本任务临时二进制、复制的前端产物、构建上下文和测试数据；留下精简结果、必要失败日志及恢复记录。不要清空共享 Go/npm/Docker cache。
- worktree 干净、提交已记录且可从保留分支/标签/默认分支找到时，用 `git worktree remove <本任务目录>`。被未提交文件阻止时先查明原因，保留实际工作；不自动 `--force`。
- 对旧版本先按实际引用和用户保留策略盘点；缺策略时至少保护当前与上一稳定版本，其他旧版本仅列清理候选。不要因“长期迭代”默认无限保留本任务可重建产物。
- 不顺便清理其他任务的 worktree、真实数据、Cookie、数据库、`~/backups` 或回滚镜像。不执行 `docker system prune`、`docker image prune -af`、`git clean -fdx` 或硬重置。

若需要批量清理用户存量文件、备份或全局镜像，先列清范围、引用与影响，按用户全局约定确认；本技能的省空间目标不提供额外删除授权。
