# 下载失败判断

## 先分类

按报错特征归到下面一类，再给建议：

- 链接无法识别：域名不在支持列表，或链接缺少歌曲/歌单 ID。
- 登录或凭证失效：出现未登录、musickey 过期、cookie 失效、401/403。
- 平台风控：出现风控、安全验证、验证码、429、`code=-462`。
- 音源或格式：出现 requested format is not available、没有可用音频格式。
- 网络：超时、连接重置、DNS 失败、代理不可用。
- 整理入库：标签写入失败、重命名失败、WebDAV 不可用。

## 判断依据

1. 先看用户给的原始报错，不要替换成笼统的"下载失败"。
2. 能确定平台时，说明是哪个平台、哪一步（识别 / 下载 / 元数据 / 整理 / 上传）。
3. 不确定时给最多两种可能，并说明怎么区分，不要列一长串猜测。

## 输出格式

- 结论一句话：哪一步失败、最可能原因。
- 下一步一到三条：具体到"重新扫码登录""换音源""等几分钟再试""检查代理"。
- 如果是配置问题，指出配置项名称，不要展示密钥值。

## 边界

- 不承诺"一定能修好"。
- 不要求用户发送 cookie、token 或账号密码。
- 不做破坏性建议，例如删除曲库、重建容器，除非用户明确要求并确认。
